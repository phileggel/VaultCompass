# v0.28.0 — Release Scope

**Branch**: `feat/v0.28.0`
**Theme**: Transaction-dialog UX polish + small backend refactors + error-model gold collapse (account BC) + two small techdebt fixes.

This is the agreed work plan for the release. Each task links back to its source in
`docs/todo.md` or `docs/techdebt.md`. Per-feature specs/contracts (where a task needs
them) are authored separately under `docs/spec/` and `docs/contracts/`.

---

## Working agreement

1. **One shared branch, one draft PR** — every task lands on `feat/v0.28.0`. A **draft PR**
   tracks the branch purely so Codecov posts a per-file coverage comment after each task
   push (verification only, **not** incremental merge). The whole batch merges at release.
2. **Workflow per task** — Workflow **B** (Simple) by default; **hybrid A/B** only when the
   task changes a business rule and so needs a `docs/spec/` (+ `docs/contracts/`) update —
   then the spec/contract slice runs first, the rest as B.
3. **Tasks are handled independently** — finish, test, review, and commit one task before
   the next. A task may be **one or several commits** (title-only conventional commits).
4. **Coverage gate after every task** — every file the task added or modified must reach
   **≥80% line coverage**. Only pass-through files are exempt and may be lower:
   `**/api.rs` and `gateway.ts` (and other thin binding/IPC pass-throughs). Verification
   flow: `just coverage-fe` / `just coverage-be` for fast in-task feedback, then push the
   task and read the **Codecov per-file comment** on the draft PR as the authoritative
   check. Note: Codecov's enforced CI gate is only **50% patch** (`codecov.yml`); the
   80%-per-file bar is a **manual read** of the per-file table, not an auto-fail — so the
   numbers must be eyeballed even when the Codecov status is green.
5. **Review after every task** — run the applicable reviewer-\* agents → `/review-triage`
   → apply follow-ups.
6. **Test- and review-fix placement** (same policy for both) — mono-commit task → fold the
   added tests and review fixes into that commit (amend); multi-commit task → put them in a
   **dedicated closeout commit** at the end of the task.
7. **Visual proof** — any task touching `.tsx`/`.css` runs `/visual-proof` before its
   commit (light + dark).

## Commit plan (per task)

The driver of mono vs multi: **every commit must independently pass the pre-commit
`just check`** (it runs TSC + clippy + tests). So any change that regenerates `bindings.ts`
or alters a command signature keeps **backend + frontend in the same commit** — otherwise
the in-between commit fails TSC. That is why most tasks are mono. Review + coverage then
fold into that single commit (mono) or a dedicated closeout commit (multi), per working
agreement #6.

- **T1 — C-BC1: 1 commit (mono).**
  `refactor: collapse account BC into a single AccountError`
  Atomic by necessity (must compile + pass clippy/tests in one shot): the collapse, the
  D2 `replay_cash_holding` boyscout, `bindings.ts` regen + any FE error-type fixups, and
  the updated/added tests all in one commit; coverage + review (a)-fixes amended in.
  _Promote review/coverage to a separate closeout commit if those fixes turn out large._

- **T2 — C-UC1: 1 commit (mono).**
  `refactor: rename use-case task sub-enums to gold` — mechanical rename; tests + review
  folded.

- **T3 — D1: 1 commit (mono).**
  `fix: drop expect() in reqwest client constructors` — 3 sites; tests + review folded.

- **T4 — B: 1 commit (mono).**
  `refactor: move id/account_id into correct/cancel DTOs` — BE + regenerated bindings + FE
  gateway/callsites atomic (a signature-only split would break FE TSC mid-way); tests +
  review folded.

- **T5 — A1+A2: 3 commits (multi).**
  1. `feat(account): holding snapshot as-of date query` — spec + contract docs + BE
     command/service/domain + `bindings.ts` + BE tests (green on its own; FE not yet using
     it).
  2. `feat: show as-of-date avg price & potential P&L on trade dialogs` — FE info lines +
     `/visual-proof` screenshots + FE tests.
  3. **Closeout** — `test: cover as-of-date holding info + apply review` — coverage gaps
     across BE/FE to ≥80% + reviewer (a)-fixes.

- **T6 — A4: 1 commit (mono).**
  `feat: add "another dividend" button to the dividend dialog` — FE + `/visual-proof` +
  tests + review folded.

- **T7 — A5: 1 commit (mono; may split to 2).**
  `feat: price dialog add-another + fuzzy asset search` — FE + `/visual-proof` + tests +
  review folded. Split the add-another button from the combobox swap only if the diff gets
  large.

- **T8 — A3: 1 commit (mono), or deferred.**
  `feat: inline arithmetic in number fields` — FE + `/visual-proof` + tests + review
  folded. Spike first; drop from v0.28.0 if it bloats scope.

**Total if everything ships**: ~10 commits (T1–T4 + T6–T8 = 7 mono, T5 = 3).

## Task details

### A1+A2 (T5) — as-of-date avg price & potential P&L on trade dialogs

Source: `docs/todo.md`. Hybrid A/B — needs spec + contract.

- **A1**: average cost price as an info line under the price field on the buy/sell dialog,
  computed as of the entered buy/sell date (or today if none).
- **A2**: potential P&L under the computed global amount on the **sell** dialog — from sell
  date, avg price, typed sell price, and qty held on that date. No info when qty or typed
  price is missing.
- Siblings: both surface as-of-date holding info and share one backend "holding snapshot as
  of date" read. Author one spec covering both rules, one contract command, build together.

### A3 (T8) — inline calc in number fields

Source: `docs/todo.md`. FE only; **UX needs refinement**. Spike first; defer out of v0.28.0
if it bloats scope.

### A4 (T6) — dividend "add another" button

Source: `docs/todo.md`. FE only — a button in the dividend dialog to record another
dividend without closing.

### A5 (T7) — price dialog "add another" + fuzzy search

Source: `docs/todo.md`. FE only. Adds an "add another price" button; asset selector becomes
the fuzzy `ComboboxField` (reused from `DividendTransactionModal`, v0.26.0); asset can be
pre-selected; date defaults to the standard stored date.

### B (T4) — `correct`/`cancel` parameter style

Source: `docs/todo.md` (backend). `correct_transaction(id, account_id, dto)` and
`cancel_transaction(id, account_id)` mix primitives + DTO; every other holding-transaction
command is DTO-only. Move `id`/`account_id` into the DTOs. Wire-visible: gateway call sites
and regenerated bindings change. No new business rule → contract doc touch only, Workflow B.

### C — error-model gold collapse (account BC) — audited 2026-06-27

Source: `docs/techdebt.md` § 2026-05-25. **Audit confirms the debt is 100% still pending
and has grown** — no collapse happened, and two new use-case composites
(`DividendApplicationError`, `FreeSharesApplicationError`) repeat the anti-pattern. The new
`context/currency/` BC is the gold reference shape (single flat `CurrencyError`).

- **BC-1 (T1) — in v0.28.0.** Collapse `account/` BC → single flat `AccountError`
  (8 types → 1). No wire change (variants keep their `code` discriminant).
- **UC-1 (T2) — in v0.28.0.** Rename use-case task sub-enums to gold; fix the 2 new
  composites. No wire change.
- **BC-2 — deferred.** Collapse `asset/` BC → single flat `AssetError` (10 types → 1);
  rename `NotFound{id}` → `AssetNotFound`/`CategoryNotFound`; absorbs the residual
  asset-side wrappers in `DeleteAssetError`/`ArchiveAssetError`. **Wire-visible** — FE
  contract + i18n + switch-arms — so it gets its own focused release.

**After v0.28.0**, the only remnant of the 2026-05-25 techdebt entry is BC-2. Keep that
entry in `docs/techdebt.md`, trimmed to BC-2 only.

### D — small techdebt fixes

- **D1 (T3)** — `.expect("reqwest client build")` in `yahoo_client.rs` +
  `currency/infrastructure/{frankfurter,ecb}_client.rs` (3 constructors). Source:
  `docs/techdebt.md` § 2026-06-06 (🔵). Own tiny `fix:` commit; convert to a typed error or
  add `clippy::expect_used` to the lint set and fix the 3 sites.
- **D2** — `replay_cash_holding` uses `Holding::restore` for fresh/upserted holdings.
  Source: `docs/techdebt.md` § 2026-06-20 (🟡). **Deferred — NOT folded into T1.** Attempted
  during T1 but the `Holding::new`/`with_id` factories return `anyhow::Result`, not
  `Result<_, AccountError>`, so calling them inside `replay_cash_holding` (which returns
  `AccountError`) needs an anyhow→`AccountError` downcast or a typed-factory migration —
  design judgement, not a mechanical swap (fails the boyscout gate, exactly as the techdebt
  entry warned). Stays in `docs/techdebt.md`, now blocked on migrating the `Holding`
  factories to typed errors.
